# End 슬라이드 이후 추가 자료 설계

## 목표

사용자가 PDF, PPTX, PNG, JPG/JPEG 파일을 여러 개 선택하고 순서를 정해 기존 Back/End 슬라이드의 마지막 뒤에 추가할 수 있게 한다. 추가 자료는 최종 PPTX, 편집기 썸네일, 자동 저장, 라이브러리 재편집 흐름에서 동일한 순서와 내용으로 유지되어야 한다.

편집기 보기는 좁은 데스크톱 폭에서 오른쪽 편집 영역이 갑자기 찌그러지는 현재 레이아웃을 바로잡고, 헤더와 본문의 좌우 여백을 같은 기준으로 맞춘다.

## 사용자 흐름

기존 5단계 마법사를 6단계로 확장한다.

1. 찬양
2. 성경 말씀
3. 설교
4. 광고
5. 추가 자료
6. 다운로드

`추가 자료` 페이지에는 여러 파일을 한 번에 선택하거나 끌어다 놓는 업로드 영역과 선택된 파일 목록을 둔다. 각 목록 행에는 파일명, 파일 형식, 예상 슬라이드 수, 위/아래 이동, 삭제 동작을 제공한다. 선택 순서가 기본 병합 순서이며 사용자가 변경한 순서를 그대로 사용한다.

최종 슬라이드 순서는 다음과 같다.

`Front → 찬양 → 기도 → 말씀 → 설교 → 기도 → 광고 → Back/End → 추가 자료`

추가 자료가 없으면 현재 결과와 완전히 동일하게 동작한다. 추가 자료만 있어도 유효한 생성 입력으로 간주한다.

## 지원 형식과 변환

### PPTX

업로드한 PPTX의 모든 슬라이드를 원래 순서대로 `mergePptxDecks()`에 전달한다. 레이아웃, 마스터, 테마, 이미지 등 기존 병합기가 보존하는 시각 리소스를 그대로 유지한다. 손상되었거나 슬라이드가 없는 PPTX는 해당 파일명을 포함한 오류를 표시하며 최종 생성은 중단한다.

### PDF

PDF.js로 모든 페이지를 브라우저에서 PNG로 렌더링한다. 각 페이지를 4:3 이미지 슬라이드 한 장으로 변환한다. 페이지는 잘라내지 않고 흰 배경 안에 `contain` 방식으로 맞춰 원래 비율을 유지한다.

### PNG 및 JPG/JPEG

이미지 파일 하나를 4:3 이미지 슬라이드 한 장으로 변환한다. EXIF 회전이 브라우저 디코더에 반영된 최종 방향을 사용하고, PDF와 마찬가지로 흰 배경 안에 원래 비율을 유지한다.

### 이미지 슬라이드 PPTX 생성기

새 `imageDeckBuilder` 모듈은 이미지 배열과 실제 픽셀 크기를 받아 하나의 독립적인 PPTX를 만든다. 번들된 4:3 템플릿에서 빈 슬라이드 구조와 마스터/레이아웃을 재사용하고 각 슬라이드에 이미지 관계 및 미디어 파트를 추가한다. 결과는 기존 `mergePptxDecks()`와 `assertPptxIntegrity()`가 처리할 수 있는 정상적인 PPTX 패키지여야 한다.

PDF 한 파일의 모든 페이지는 하나의 이미지 deck으로 묶고, 일반 이미지 파일은 인접한 이미지들을 한 deck으로 묶을 수 있다. 그러나 최종 병합 순서는 항상 사용자 파일 목록의 순서를 기준으로 한다.

## 상태와 구성 요소

`App`은 `AdditionalFile[]` 상태를 소유한다. 각 항목은 세션 내 고유 ID, 파일명, MIME/확장자에서 정규화한 형식, 원본 `ArrayBuffer`를 가진다.

새 `AdditionalFilesSection` 구성 요소는 다음만 담당한다.

- 드롭 및 파일 선택 입력
- 지원 형식 검증
- 목록 표시
- 위/아래 이동
- 삭제
- 변환 진행 또는 파일별 오류 상태 표시

PPTX 변환과 병합은 UI 구성 요소가 아니라 별도 라이브러리 모듈에서 수행한다. 이를 통해 파일 순서, 형식 검증, PDF/이미지 변환, PPTX 패키지 생성을 단위 테스트할 수 있게 한다.

편집기 보기에서는 기존 마법사 구성 요소와 같은 `AdditionalFilesSection` 인스턴스를 함께 표시한다. 추가 자료 썸네일 행은 클릭하면 이 섹션으로 스크롤한다. `DeckOverviewKind`에는 추가 자료 종류를 나타내는 값을 추가하고 각 실제 슬라이드와 개요 행이 1:1로 정렬되도록 실제 변환 결과의 슬라이드 수를 사용한다.

## 병합 흐름

`buildMergedDeck()`은 현재와 같이 Back/End deck까지 만든 뒤 추가 자료를 순서대로 처리한다.

1. PPTX는 원본을 바로 병합한다.
2. PDF는 모든 페이지를 이미지 deck으로 변환한 뒤 병합한다.
3. PNG/JPG/JPEG는 이미지 deck으로 변환한 뒤 병합한다.
4. 파일마다 실제 슬라이드 수를 검사해 overview 항목을 추가한다.
5. 모든 병합이 끝난 결과에 `assertPptxIntegrity()`를 실행한다.

마지막 병합만 DEFLATE를 사용하고 중간 병합은 가능한 한 STORE를 사용해 기존 성능 특성을 유지한다. 변환 중에는 생성/저장 버튼을 비활성화하고 기존 진행 상태 문구를 사용한다.

## 라이브러리 저장과 복원

추가 자료 원본은 하나의 ZIP 파일로 묶어 PPT 라이브러리 항목에 저장한다. 새 파일 종류 이름은 `additionalFiles`로 한다.

ZIP에는 다음을 포함한다.

- `manifest.json`: 버전, 파일 순서, ZIP 내부 경로, 원래 파일명, 정규화한 형식
- `files/0000-*`, `files/0001-*` 등 원본 바이트

브라우저 클라이언트와 Worker의 파일 종류 목록을 동시에 확장해 기존 1 MiB 청크 업로드/다운로드, 100 MB 합계 제한, 삭제 및 동기화 흐름을 그대로 사용한다. 과거 라이브러리 항목에는 이 파일이 없으므로 `null`을 정상값으로 취급한다.

라이브러리에서 편집을 열 때 ZIP을 검증하고 파일 목록을 복원한다. ZIP이나 manifest가 손상되면 기존 덱 입력은 계속 복원하되 추가 자료는 비우고 경고를 표시한다. 손상된 일부 파일만 조용히 누락하지 않는다.

자동 저장 fingerprint에는 추가 자료의 순서, 파일명, 크기를 포함한다. 순서 변경, 추가, 삭제가 모두 저장을 유발해야 한다.

## 편집기 레이아웃 수정

현재 900px 이하에서만 한 열로 전환하기 때문에 화면 폭이 900px에서 901px로 바뀔 때 오른쪽 편집 영역이 약 852px에서 509px로 급격히 줄어든다. 고정 312px 왼쪽 열과 32px gap이 오른쪽 편집기에 필요한 최소 폭을 고려하지 않는 것이 원인이다.

편집기 레이아웃은 다음 원칙으로 수정한다.

- 헤더와 앱 본문에 같은 `--page-gutter`와 최대 너비를 적용해 양쪽 바깥 여백을 정확히 맞춘다.
- 2열 상태에서는 왼쪽 슬라이드 패널을 `minmax(280px, 312px)`, 오른쪽 영역을 `minmax(0, 1fr)`로 정의한다.
- 오른쪽 편집 영역이 실사용 가능한 폭을 확보하지 못하는 구간에서는 더 이른 breakpoint에서 1열로 전환한다.
- 1열에서는 슬라이드 패널을 비고정으로 두고 제한된 높이 안에서 스크롤하게 한다.
- `main`에 `min-width: 0`을 명시해 내부 flex/grid 콘텐츠가 전체 페이지 폭을 밀어내지 않게 한다.

검증 기준은 900, 901, 1024, 1200, 1280, 1440, 1920px 폭에서 수평 스크롤이 없고, 헤더와 본문 좌우 경계가 일치하며, 2열 상태의 오른쪽 영역이 정한 최소 폭보다 좁아지지 않는 것이다.

## 오류 처리와 제한

- 지원하지 않는 확장자와 MIME 형식은 업로드 시 거부하고 허용 형식을 안내한다.
- 파일 이름만 믿지 않고 PNG/JPEG/PDF/PPTX의 파일 signature 또는 패키지 구조를 변환 시 검증한다.
- 빈 파일, 암호화된 PDF, 손상된 이미지, 손상된 PPTX는 파일명을 포함한 오류로 중단한다.
- 한 항목의 저장 합계가 기존 100 MB 제한을 넘으면 현재 라이브러리 오류를 그대로 표시한다.
- 브라우저 메모리 사용을 줄이기 위해 PDF 문서와 object URL은 변환 후 반드시 해제한다.
- 추가 자료 개수에 별도 임의 제한을 두지 않되 PPTX 무결성 검사와 기존 5000장 서버 제한은 유지한다.

## 테스트 전략

### 단위 테스트

- 지원 형식 판별과 잘못된 파일 거부
- 파일 이동과 삭제 후 순서
- PNG/JPEG 한 파일이 슬라이드 한 장이 되는 이미지 deck
- 여러 이미지의 순서와 `contain` 배치 좌표
- 이미지 deck의 관계, 콘텐츠 타입, 미디어 파트 및 PPTX 무결성
- 추가 자료 ZIP encode/decode 왕복과 손상 manifest 거부
- deck source 및 auto-save fingerprint에 추가 자료 반영
- 클라이언트와 Worker 파일 종류 목록 일치

### 통합 테스트

- Back 슬라이드의 마지막 다음에 PNG, PDF 페이지, PPTX 슬라이드가 사용자 파일 순서대로 나타남
- 생성된 슬라이드 수와 presentation slide ID 수가 일치
- 모든 관계가 실제 패키지 파트를 가리킴
- 추가 자료가 없을 때 기존 결과가 유지됨

### E2E 테스트

- 6단계 마법사와 `추가 자료` 페이지 이동
- 여러 파일 업로드, 순서 변경, 삭제
- 편집기 썸네일에서 추가 자료가 Back 뒤에 표시되고 클릭 시 업로드 섹션으로 이동
- 다운로드한 PPTX의 실제 슬라이드 순서 검증
- 라이브러리 저장 후 다시 편집했을 때 파일명과 순서 복원
- 주요 viewport에서 좌우 여백, breakpoint, 수평 overflow 검증

## 문서 변경

README의 생성 순서, 단계 수, 편집기 설명, 라이브러리 보관 파일, 지원 추가 자료 형식을 새 동작에 맞게 갱신한다.
